## 2. Capabilities that recur across mature products

- **Isolated, ephemeral execution environment per task** (sandbox/VM/microVM/container). Why it matters: keeps agent mistakes and secret exposure contained, and lets multiple tasks run in parallel without interfering. Seen in: GitHub Copilot coding agent (GitHub Actions sandbox), OpenAI Codex (cloud sandbox), Cursor (Firecracker microVM), Devin (cloud VM/"machine"), Google Jules (Google-managed VM), OpenHands (Docker sandbox). [GitHub Docs](https://docs.github.com/en/enterprise-cloud@latest/copilot/how-tos/agents/copilot-coding-agent/customizing-the-development-environment-for-copilot-coding-agent), [Cursor docs](https://cursor.com/docs/cloud-agent/security-network), [Google Developers Blog](https://developers.googleblog.com/en/meet-jules-tools-a-command-line-companion-for-googles-async-coding-agent/)

- **Branch isolation with the agent never touching protected branches directly.** Why it matters: preserves the existing branch-protection/required-review model instead of needing a parallel trust system. Seen in: GitHub Copilot (`copilot/*` branch scoping, requester cannot self-approve), Cursor (own branch + draft PR), Devin (session branch + PR, stacked PRs). [GitHub Docs](https://docs.github.com/en/copilot/responsible-use/copilot-cloud-agent), [Cursor docs](https://cursor.com/docs/cloud-agent)

- **Plan-before-code, visible to the human.** Why it matters: lets a developer redirect a wrong approach before tokens/time are spent on implementation, and gives reviewers a rationale trail. Seen in: GitHub Copilot coding agent, Devin, Google Jules, Atlassian Rovo Dev, GitLab Duo (issue→MR flow), Amazon Q `/transform` (plan requires explicit approval), Aider (architect mode). [GitHub Blog](https://github.blog/ai-and-ml/github-copilot/assigning-and-completing-issues-with-coding-agent-in-github-copilot/), [Devin docs](https://docs.devin.ai/release-notes/2026), [AWS](https://aws.amazon.com/q/developer/transform/)

- **Automatic test-run-and-iterate loop before opening/finalizing the PR.** Why it matters: reduces the "looks right but doesn't build/pass" failure mode that erodes trust in agent output. Seen in: OpenAI Codex, Google Jules, GitHub Copilot coding agent, Devin, GitLab Duo. [OpenAI](https://openai.com/index/introducing-codex/), [Devin docs](https://docs.devin.ai/release-notes/2026)

- **Automated security/quality scanning inline in the agent's own loop, before human review.** Why it matters: shifts security review left so a human reviewer isn't the last line of defense against agent-introduced vulnerabilities. Seen in: GitHub Copilot coding agent (CodeQL, secret scanning, dependency review, Copilot Autofix), GitLab Duo (Security Review Flow with CWE classification), Atlassian Bitbucket Agentic Pipelines (vulnerability-fix workflow), Devin Review (confidence/severity-labeled findings). [GitHub Changelog](https://github.blog/changelog/2026-06-09-security-validation-for-third-party-coding-agents/), [GitLab docs](https://docs.gitlab.com/user/duo_agent_platform/flows/foundational_flows/security_review/)

- **Session/thread transcript as the audit artifact, linked from the commit or PR.** Why it matters: makes an agent's reasoning and tool calls inspectable after the fact — necessary for both debugging and compliance. Seen in: GitHub Copilot (session log linked from commit message), Sourcegraph Amp (threads at ampcode.com), Devin (Devin Review link in every Slack post), GitLab Duo (AI audit event reports, beta). [GitHub Changelog](https://github.blog/changelog/2026-01-26-introducing-the-agents-tab-in-your-repository/), [GitLab 19.2 release](https://about.gitlab.com/press/releases/2026-07-16-gitlab-19-2-brings-governed-agentic-automation/)

- **Ticket system as the unit of work, not chat.** Why it matters: keeps agent-initiated changes traceable to a requirement and slots into existing PM/triage processes rather than creating a shadow workflow. Seen in: GitHub Copilot (assign issue), Atlassian Rovo Dev/Agents in Jira, Devin (Jira/Linear), Factory.ai (Linear/Jira "native unit of work"), GitLab Duo (issue→MR flow), Amazon Q (Jira-triggered via automation). [Atlassian blog](https://www.atlassian.com/blog/bitbucket/ai-powered-workflows-rovodev), [Factory/NEA blog](https://www.nea.com/blog/factory-the-platform-for-agent-native-development)

- **Usage-metered rather than seat-metered cost model for agent work specifically.** Why it matters: agent tasks can run for minutes to hours consuming many tokens/tool calls, so flat seat pricing doesn't map to cost; vendors are moving to task/credit/token metering with admin-settable budgets. Seen in: GitHub Copilot (AI Credits, June 2026), Google Jules (task-count tiers with concurrency caps), Sourcegraph Amp (thread-length-driven cost). [CloudZero](https://www.cloudzero.com/blog/github-copilot-cost/), [HackUp](https://hackup.ai/ai-plans/jules/)

## 3. Patterns for resumability, retries and human handoff

- **Explicit pause/resume with a "tell me what changed" contract.** Devin's documented best practice: pause the agent before a human makes manual IDE edits, then leave a short note in the session chat before resuming so Devin reconciles its state with the human's changes — an informal but explicit handoff protocol rather than automatic merge-conflict resolution. [Fastio guide](https://fast.io/resources/devin-ide-guide/), [Devin docs](https://cli.devin.ai/docs/changelog/stable)
- **Session/state snapshotting to avoid re-provisioning on resume.** Cursor's environment snapshots are encrypted point-in-time VM disk copies that let an agent resume without re-cloning the repo or re-running setup — this decouples "pause" from "cost of restart." [Cursor docs](https://cursor.com/docs/cloud-agent/setup)
- **Programmatic pause/resume as an SDK primitive, not just a UI affordance.** OpenHands exposes `conversation.pause()` and `conversation.run()` directly in its SDK, plus a `confirmation_state` mechanism so an operator can gate specific actions (e.g., destructive commands) behind human confirmation mid-run — this is closer to a policy engine than a simple pause button. [OpenHands docs](https://docs.openhands.dev/sdk/guides/convo-pause-and-resume)
- **Retry-with-legible-error rather than silent failure.** Devin's CLI now surfaces upstream errors (quota exhaustion, 5xx, dropped connections) as warnings with an explicit retry hint in the REPL instead of raw stack traces — a small but concrete example of designing for graceful degradation in long-running agent sessions. [Devin CLI changelog](https://docs.devin.ai/cli/changelog/stable)
- **Decomposition into a reviewable, independently-mergeable stack as a substitute for one giant retry.** Devin's Stacked PRs break a large task into a chain of smaller PRs; addressing review comments on one PR triggers automatic rebase of downstream PRs — this reduces the blast radius of a failed or rejected step without discarding the whole task. [Devin blog](https://devin.ai/blog/introducing-pr-stacks)
- **Human-in-the-loop as a first-class graph primitive in orchestration frameworks.** LangGraph is specifically positioned around checkpointed state per graph node, enabling both resumability and human-approval interrupts as part of the graph definition rather than bolted-on session management — this is the most structural (framework-level) resumability pattern found. [LangChain framework comparison](https://www.langchain.com/resources/ai-agent-frameworks)
- **Risk-tiered autonomy as a failure-avoidance strategy rather than a retry strategy.** Factory's Droid Exec defaults to read-only "spec-mode" and requires an explicit `--auto` flag (with risk tiers) to permit edits/commands, and "fails fast on permission violations with clear errors" — the design goal is to prevent unsafe autonomous action in CI rather than to recover gracefully from one. [Factory docs](https://docs.factory.ai/droid-exec/overview)

## 4. Day-to-day interaction patterns that reduce friction

- **Assign like a teammate.** GitHub Copilot's core UX move is that assigning an issue to Copilot uses the exact same affordance as assigning it to a human — no new tool to learn, and the issue tracker itself becomes the task queue. [GitHub Blog](https://github.blog/ai-and-ml/github-copilot/assigning-and-completing-issues-with-coding-agent-in-github-copilot/)
- **Chat-native handoff inside existing team channels.** Both Devin and Cursor let a developer @-mention the agent inside an existing Slack thread and have it read the full thread for context before acting, rather than requiring the developer to re-explain the problem in a separate tool. Devin additionally supports a `!channel` override and a `!agent` bang-command to force a full session vs. a lighter "ask" mode from inside Slack. [Cursor forum](https://forum.cursor.com/t/cursor-is-now-available-in-slack/106350), [Devin release notes](https://docs.devin.ai/release-notes/2026)
- **CLI as a peer surface to the IDE and web, not an afterthought.** Google Jules, Devin, Sourcegraph Amp, Aider, and Factory's Droid all ship a CLI with parity for common actions (`/new`, `/remote` dashboards for Jules; `droid exec` for Factory; full session for Aider) — this matters for developers who live in a terminal/tmux workflow and don't want to context-switch to a browser to kick off or check on agent work. [Google Developers Blog](https://developers.googleblog.com/en/meet-jules-tools-a-command-line-companion-for-googles-async-coding-agent/), [Factory docs](https://docs.factory.ai/droid-exec/overview)
- **A repo-level "mission control" view instead of a chat history.** GitHub's Agents tab surfaces every agent session for a repository — status, token usage, session length, grouped tool calls, inline diffs — as a dedicated dashboard, separate from both the PR list and the chat UI, explicitly modeled as a place to triage many concurrent agent runs at once. [GitHub Changelog](https://github.blog/changelog/2026-01-26-introducing-the-agents-tab-in-your-repository/)
- **Parallel task queuing as the default mental model, not a power-user feature.** OpenAI's Codex and Google Jules are both explicitly pitched around queuing several tasks and letting them run concurrently while the developer works on something else, rather than a single synchronous chat session — this reframes the developer's role from "pair programmer" to "task dispatcher/reviewer." [OpenAI](https://openai.com/index/introducing-codex/), [HackUp](https://hackup.ai/ai-plans/jules/)
- **Atomic, auto-committed history as its own low-friction audit UI.** Aider's approach — one git commit with a generated message per discrete change — means `git log --oneline` is the review surface; no separate dashboard is needed because the tool piggybacks entirely on a workflow developers already use. [Aider review](https://codegen.com/ai-tools/aider/)
- **Interface-agnosticism as an explicit design goal for enterprise tools.** Factory's Droids and Amazon Q Developer agents are both marketed as working identically across IDE, CLI, Slack, web, and (for Q) GitLab — the stated goal being that a developer should not have to change tools depending on which agent picked up the ticket. [NEA blog](https://www.nea.com/blog/factory-the-platform-for-agent-native-development)
