Agent Manager as an Agentic SDLC System

Capability roadmap. 5 September 2026. Sources: an internet survey of thirteen agentic SDLC products and frameworks, a file-level gap analysis of this repository, and two days of live Runbook A runs on ticket SCN-402.

Summary

The system already does the things that mature products converge on: an isolated stack per run, a visible plan gated by a hook, a failing test before a fix, verification with an independent monitor, an evidence bundle in the PR, and as of today, restart, resume and clone of runs. On SCN-402 it went from ticket to an open PR with evidence, PR #459, with the last step restarted in place rather than re-run from scratch.

What blocks daily use is not missing agents. It is that routing and environment knowledge lives in agent prose instead of data the runner can act on, and that the developer still babysits. The roadmap below orders fixes by which blocker they remove, and most of the first tier is small.

What the live runs taught

  • Prompts carried facts they could not verify. The intake agent searched a hidden directory with tools that skip hidden directories. The provisioner ran from inside a container and tested host ports. Both fixed by putting facts in the runner's step header and the prompt, but the pattern will recur wherever knowledge is prose.
  • Turn budgets were set for small repos. Three steps died on error_max_turns in a large monorepo. Budgets doubled. A time and token cap is the real control.
  • The monitor only sees output text. Steps that wrote artifacts but did not list them were sent back. Now every step is told to end with a directory listing. Cheap, and it removed a whole class of retries.
  • Failed runs were disposable. Every prompt fix cost a 35-minute rerun. Restart from a step closed that. The PR step fix was validated in eight minutes instead.
  • Stop does not abort the agent. A run marked stopped kept executing and opened the PR anyway. The runner must cancel the SDK call, not just the record.
  • Re-syncing a workflow orphans its runs. The template sync regenerates step ids, so older runs no longer matched their workflow. Restart now aligns ids by position; the sync should preserve ids.

Decisions needed from you

  1. Bot account for pushes and PRs, or continue under personal identities.
  2. Whether .agent/plan.md should be committed into product repos, as PR #459 did, or travel only in the evidence bundle.
  3. Resolve the CONFIRM entries in the registry before it becomes the routing source. A wrong value would misroute a ticket instead of failing a check.
  4. Whether the pipeline may ever open a PR without a pause before the push step. Today the answer is set per run in the modal.

Non-goals

  • Auto-merge. Human merge stays the gate.
  • A generic SDLC platform. The registry, compose conventions and branch policies are this estate's.
  • An approval step inside the run in place of PR review.
