>
> It read `.agent/evidence-run/` from a pull request's checkout. Evidence no
> longer goes into a product repository — it stays in the run directory, is
> served by the app at `/api/runs/:id/artifacts`, and is quoted in full in the
> pull request body. With nothing writing that directory, the check could only
> ever report "no evidence": a check that looks like enforcement and is not.

> inside the container, and refuses to open a pull request if it fails. That is
> the gate now, and it runs before the PR exists rather than after.

> reasoning in it.

# Evidence bundle

## What it is

An agent-authored PR should not ask a reviewer to trust an adjective
("verified", "tested", "should be safe"). It should carry proof: the test
that reproduced the bug, the same test passing after the fix, the regression
run, and enough identity/provenance metadata that a reviewer can tell what
model, what plugin version, and what agent identity produced the change.
That proof, structured to one schema, is the **evidence bundle**
(`schemas/evidence-bundle.v0.1.schema.json`, v0.1).

Three scripts turn raw CI artifacts into that bundle and then into what a
reviewer actually reads:

| Script | Job |
|---|---|
| `scripts/assemble-bundle.mjs` | Reads a run directory (below), builds a bundle. Never invents a field — a missing artifact means the field is left out, not defaulted. |
| `scripts/validate-bundle.mjs` | Enforces the schema plus the semantic rules a JSON Schema can't express (pre-fix oracle must FAIL, post-fix must PASS, multi-repo fixes need `merge_order`). |
| `scripts/bundle-summary.mjs` | Renders the bundle to the fixed six-row, one-screen Markdown summary a reviewer reads before opening the diff. |

`.github/workflows/evidence-bundle.yml` (repo root) is what turns this from
"a document an agent can produce" into "a document a PR cannot merge
without" — **if the CI wiring below is trusted; see the caveats at the
bottom, they are not a footnote.**

## The run-directory contract

This is the interface between whatever process ran the fix (currently:
nothing automated — see caveats) and `assemble-bundle.mjs`. It is documented
in full, with the exact JSON shape and hashing rules, in the header comment
of `scripts/assemble-bundle.mjs` — that comment is the source of truth; this
is a summary.

A run directory contains:

**Required**
- `meta.json` — identity claims, labels, declared test metadata (ticket,
  watch, work_type, class, product, blast_radius, identity, model,
  plugin_version, stack, oracle/oracle_after/regression declarations, fix
  metadata, cost). Notably does **not** carry any test verdict or hash —
  those are computed from the other files below, never self-reported.
- `context-packet.json` — the context packet the agent worked from. Hashed
  (full sha256) into `context_packet_hash`.
- `intent.md`, `plan.md` — hashed (first 12 hex chars of sha256) into
  `intent_sha` / `plan_sha`.
- `summary.md` — the one-screen summary, carried through verbatim into
  `summary_md`. Authored content, like intent/plan — **not** generated by
  `bundle-summary.mjs`; that script produces the check body, not this file.
- `oracle-before.xml`, `oracle-after.xml`, `regression.xml` — xunit output.
  Hand-parsed (no XML library): failures + errors > 0 ⇒ FAIL, else PASS.
  `verdict` is present only if the file exists and parses as xunit.

**Optional**
- `spec.md` — present only when the watch declares `requires: [spec]`.
  Hashed into `spec_sha`; `null` when absent (a legitimate schema value).
- `trace.zip` — Playwright trace. Recorded as a filename in `trace` when
  present, `null` when absent.

A run directory missing a required file produces a bundle the validator
**rejects** — that rejection, not a clever assembler, is the entire
enforcement mechanism.

## Running the three scripts by hand

```bash
cd engineering

# 1. Assemble a bundle from a run directory
node scripts/assemble-bundle.mjs --run-dir /path/to/run-dir --out bundle.json
# exit 0 = valid bundle written; exit 1 = written anyway, for inspection, with problems on stderr

# 2. Validate an existing bundle (assemble already does this internally;
#    useful on its own when iterating on a hand-edited bundle.json)
node scripts/validate-bundle.mjs bundle.json

# 3. Render the one-screen reviewer summary
node scripts/bundle-summary.mjs bundle.json
```

All three are dependency-free Node (`node scripts/*.mjs`, no `npm install`).
Their own test suites:

```bash
node scripts/test-validate-bundle.mjs
node scripts/test-assemble-bundle.mjs
node scripts/test-bundle-summary.mjs
```

## The CI workflow

`.github/workflows/evidence-bundle.yml` runs two independent checks on every
`pull_request`:

- **`evidence-bundle`** — locates a workflow artifact named
  `evidence-run-<PR head SHA>`, downloads it as the run directory, then runs
  assemble → validate → render, and posts the result via the Checks API
  (`checks.create`, `head_sha` = the PR's head commit). No artifact, or an
  artifact missing required evidence, is posted as a **failing** check with
  the specific missing-evidence reasons in its output.
- **`diff-size`** — fails a PR that changes more than 400 lines or 10 files,
  counted after excluding test paths (`**/tests/**`, `**/*.test.*`,
  `**/*.spec.*`, `**/test-*.mjs`, …) and generated/build paths (`dist/`,
  `.output/`, `.nuxt/`, lockfiles, …). The check's own output states why:
  reviewer minutes per PR only stay flat as the agent-authored share of PRs
  rises if PRs stay small enough to review at a constant rate. It is a
  capacity control, not a style rule — the output says so explicitly so a
  developer who hits it knows to split the PR or ask for the limit to be
  raised with a stated reason, not to treat it as arbitrary.

Every action in the workflow is pinned to a commit SHA, not a floating tag
(`actions/checkout`, `actions/setup-node`, `actions/github-script`,
`actions/download-artifact`), and the workflow declares only the
permissions it uses: `checks: write`, `pull-requests: write`, `contents:
read`, plus `actions: read`. That fourth scope is one more than the task
brief listed — it is required because locating and downloading the
evidence-run artifact both call the GitHub Actions API
(`listArtifactsForRepo`, cross-run `download-artifact`), which returns 403
without it. Omitting it would make `evidence-bundle` fail every PR with "no
artifact found" for the wrong reason (permission denied, not missing
evidence) — exactly the kind of check that looks like it's working but
isn't. It is read-only, so the workflow stays least-privilege.

## What was verified, and how (2026-09-03)

**Verified locally:**
- `.github/workflows/evidence-bundle.yml` parses as valid YAML
  (`python3 -c "import yaml; yaml.safe_load(open('.github/workflows/evidence-bundle.yml'))"`).
- Every `actions/github-script` block's embedded JavaScript parses cleanly
  (`node --check` against each script body, wrapped in an async function to
  match the runtime github-script actually executes under).
- All five existing suites still pass unchanged:
  `test-validate-bundle.mjs`, `test-assemble-bundle.mjs`,
  `test-bundle-summary.mjs`, `test-hooks.mjs`, `test-validate-registry.mjs`.
- A hand-built fixture run directory, matching the contract above, was run
  through all three scripts end to end: `assemble-bundle.mjs` produced a
  bundle that `validate-bundle.mjs` accepted, and `bundle-summary.mjs`
  rendered a correct six-section summary from it.
- The same fixture with `oracle-before.xml` deleted was confirmed to make
  `assemble-bundle.mjs` exit 1 with `bundle.oracle: missing required key
  "verdict"` — the missing-evidence-fails-the-check path works as designed
  at the script layer.
- A real finding from building the fixture: setting `fix.merge_order: null`
  for a single-repo fix (the shape shown as an example in
  `assemble-bundle.mjs`'s own header comment) is **rejected** by the schema
  — `merge_order` is typed `array` only, not nullable, and must be omitted
  entirely when there is one repo. The header comment's illustrative
  `meta.json` example is misleading on this point; the working fixture in
  `scripts/test-assemble-bundle.mjs` omits the key, which is correct.

**NOT verified — written but unverified against a real PR:**
- The entire Checks API path: locating an `evidence-run-<sha>` artifact via
  `actions.listArtifactsForRepo`, downloading it cross-run via
  `actions/download-artifact`, and posting via `checks.create`. None of this
  has executed against a real `pull_request` event, a real `GITHUB_TOKEN`,
  or a real GitHub Actions runner. It has been read carefully and is
  believed correct, but "believed correct" is not the same claim as
  "verified" — do not treat a green traffic light on this workflow as
  proof it works until it has actually run once on a real PR.
- Nothing currently uploads an `evidence-run-<sha>` artifact. The workflow's
  assumption about that artifact's name and shape is stated at the top of
  the workflow file itself; until some producer (most likely Runbook A's
  `sdlc-evidence-and-pr` step) actually creates it, `evidence-bundle` will
  correctly — but uselessly — fail every PR with "no artifact found".

## This is not yet a gate

Even once the CI path above is verified end to end, **a red `evidence-bundle`
check does not by itself stop a bad PR from merging.** Two things are
missing, both out of scope for this plan (they need org admin):

1. **Branch protection** requiring the `evidence-bundle` and `diff-size`
   checks to pass before merge is not configured. Without it, these checks
   are informational — a PR can merge while they show red.
2. **Separate agent identities.** The bundle's `identity` field exists so a
   reviewer can see which agent account authored a change, on the
   assumption that the authoring identity is *not* the identity that can
   approve it. That separation does not exist yet. Until it does, the same
   identity that wrote the fix can approve its own PR, and nothing here
   stops that.

A check that *looks* like a control but isn't is worse than no check at
all, because people start trusting it. Treat everything in this document as
"the plumbing is built and locally tested" — not as "PRs are now gated."
